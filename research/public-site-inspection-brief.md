# Tambahan pengguna: reverse engineering dari situs publik

Inspeksi https://perkara.ai/#fitur dan thread akun pembuat, termasuk screenshot/video publik. Definisikan reverse engineering di sini sebagai observasi perilaku yang ditampilkan dan rekonstruksi kontrak domain/API untuk prototype kita sendiri, bukan akses backend privat atau klaim mengetahui implementasi internal.

Buat research/public-behavior-map.md dengan kolom: sumber URL/visual, perilaku terlihat, data/input-output yang dibutuhkan, invariant backend yang disarankan, status observasi vs inferensi, dan uji demo minimal. Jangan menyalin aset branding atau kode proprietary. Tidak perlu login app PerkaraAI, probing API privat, scan, atau bypass akses. Jika screenshot/video tidak dapat diakses, tulis batasan dan jangan mengarang tampilannya.

Hubungkan observasi ke alur ingest -> struktur -> klaim beratribusi -> relasi -> premis/sintesis -> jawaban bersumber. Bedakan citation valid secara lokasi dari klaim benar secara makna. Minta reviewer menguji kontrak ini dengan negasi, rencana vs kejadian, dan dokumen yang bertentangan.

Utamakan UI untuk membuktikan backend, bukan meniru tampilan. Selesaikan riset council bounded terlebih dahulu. Jangan terus memperluas referensi sampai tidak ada waktu implementasi dan demo.
